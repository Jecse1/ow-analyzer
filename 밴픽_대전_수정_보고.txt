[STEP 0 조사 — 시퀀스/턴 검증 위치]
  - 밴(순차 턴제, 유지): 서버 apply_ban()이 team!=turn 이면 NOT_YOUR_TURN.
  - 픽: 서버 apply_pick_toggle()/_slot_can_take()에는 "턴 검사가 없음". phase/자기팀 락만 검사.
    → 픽은 이미 '팀당 동시 진행' 구조. 사용자가 인식한 "순차"는 실제로는
      전체상태 브로드캐스트로 상대 픽이 실시간 노출된 것(=블라인드 아님)에서 온 것.

[서버 층 — 정상 확인]
  (A) 정적: state.py 의 pickSlots는 {"A":[None]*5,"B":[None]*5} 로 팀별 '독립 리스트 리터럴'.
      [[None]*5]*2 류 aliasing 없음. apply_pick_toggle은 state["pickSlots"][team]만 변경.
      미러픽 금지/상대 참조 로직 자체가 존재하지 않음.
  (B) 동적: WS 클라 2개를 in-process로 붙여 인터리브 픽 재현 →
      A가 doomfist(탱커) 픽 중에도 B 슬롯은 비어 있었고, B가 ramattra(다른 탱커) 픽 성공.
      즉 "A의 픽이 B 슬롯으로 새거나 B 선택을 제한"하지 않음. 서버 무결.

[클라 층 — 결함 특정 (2브라우저 실재현)]
  - 파일: frontend/src/banpick/BanpickApp.tsx
  - 결함: "원격 스냅샷을 로컬에 반영"하는 useEffect가 브로드캐스트마다
      setActiveSlot(remote.activeSlot), setPickSlots(remote.pickSlots) 등으로
      '내 팀의 activeSlot(슬롯 포커스) + 파생 filterRole(역할 그리드)'까지 무조건 덮어씀.
  - 재현 트리거(캡처됨):
      1. 탭 B(팀 B)에서 힐러 슬롯으로 포커스 이동 → 그리드가 힐러로 바뀜(activeSlot=3).
      2. 탭 A(팀 A)가 딜러(리퍼) 픽 → 브로드캐스트 도착.
      3. 탭 B의 activeSlot이 3(힐러)→1(딜러, 서버의 B값)으로 '리셋', 그리드도 힐러→딜러로 튕김.
  - 사용자 증상 매핑: 상대가 픽할 때마다 내 선택 상태가 초기화되어
      "고르던 영웅을 못 바꾼다"로 체감. (문자 그대로의 'B 슬롯에 라마트라가 들어감'은
      현재 빌드에선 서버가 슬롯을 분리 유지하여 재현되지 않음 — 재현되는 실 결함은 위 로컬상태 클로버링.)
  - 왜 기존 동치성 테스트가 놓쳤나: test_full_draft가 'A 5픽 → B 5픽' 순차만 검증하고,
      양 팀 인터리브 입력 + 클라 재동기화 상황을 모델링하지 않음.
